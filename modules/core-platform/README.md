# core-platform

Foundation service for the InfinityRx platform. Owns the `core` PostgreSQL
schema (tenants, users, roles, audit log, notifications, jobs, files,
exclusion screening).

## Local Setup

```bash
# from repo root
source .venv/bin/activate
docker compose up -d postgres redis rabbitmq
docker exec -i infinityrx-postgres psql -U infinityrx -d infinityrx \
    < infrastructure/docker/init-schemas.sql
cp .env.example .env.local  # then edit secrets
python -m shared.utils.preflight
```

## Migrations (Alembic)

Migrations are module-namespaced under `modules/core-platform/alembic/`.
The Alembic env.py loads settings from `shared.config.get_settings()` so
the database URL always tracks `.env.local`.

```bash
# Apply all pending migrations
alembic -c modules/core-platform/alembic.ini upgrade head

# Create a new autogenerated revision
alembic -c modules/core-platform/alembic.ini revision \
    --autogenerate -m "describe your change"

# Roll back one step
alembic -c modules/core-platform/alembic.ini downgrade -1
```

The baseline migration `0001_core_baseline` creates every table listed in
`docs/prd/prd-core-platform.md` section 2, inside the `core` schema. The
Alembic bookkeeping table also lives in the `core` schema
(`version_table_schema="core"`) so it never collides with other modules'
migration history.

## Tests

```bash
pytest                         # full suite
pytest --cov --cov-fail-under=95
```

Integration tests use the running docker-compose Postgres and isolate
themselves into per-test schemas via SQLAlchemy's `schema_translate_map`,
so they run in parallel without clobbering each other or the developer's
local data.
